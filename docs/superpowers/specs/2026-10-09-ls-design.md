# Simplified `ls(1)` Design

## Purpose

Build a simplified `ls` utility from scratch in C for a FreeBSD grading
environment. The observable behavior is defined by the supplied three-page
NetBSD `ls(1)` manual, not by GNU `ls` or by options outside that manual.

The finished submission is a local project only. It will contain source and
header files, a portable Makefile, an English README report, tests, and a
`.gitignore`. Creating or publishing a GitHub repository is out of scope.

## Supported Interface

The command syntax is:

```text
./my_ls [-AacdFfhiklnqRrSstuw] [file ...]
```

The executable is named `my_ls` so it cannot accidentally invoke or overwrite
the system `ls` during development and testing.

All options in the supplied synopsis are required:

- `-A`: include dot-prefixed entries except `.` and `..`; this behavior is
  enabled automatically for the superuser.
- `-a`: include every entry, including `.` and `..`.
- `-c`: use status-change time for `-t` sorting and `-l` output.
- `-d`: print directory operands as entries and do not dereference symbolic
  links supplied as operands.
- `-F`: append `/`, `*`, `@`, `%`, `=`, or `|` according to entry type.
- `-f`: do not sort.
- `-h`: show values affected by `-s` or `-l` in human-readable byte units.
- `-i`: prefix each entry with its inode number.
- `-k`: show `-s` block counts in 1024-byte units.
- `-l`: use long format.
- `-n`: use long format with numeric owner and group IDs.
- `-q`: replace non-printable pathname bytes with `?`.
- `-R`: recursively list subdirectories.
- `-r`: reverse the selected ordering.
- `-S`: sort by size, largest first.
- `-s`: prefix each entry with the allocated block count.
- `-t`: sort by the selected timestamp, newest first.
- `-u`: use access time for `-t` sorting and `-l` output.
- `-w`: print pathname bytes without `-q` replacement.

No long options or additional real-world `ls` options will be added.

## Behavioral Rules

### Operands and directories

With no operands, the utility lists `.`. With multiple operands, non-directory
operands are emitted before directory contents. File operands and directory
operands form separate sort groups and use the active sort mode.

A symbolic-link operand that resolves to a directory is treated as a directory
unless `-d` is active. Symbolic links encountered while reading a directory
are never followed for recursion. Recursive traversal always excludes `.` and
`..`, even when `-a` is active.

Each directory shown when more than one operand was supplied, or during a
recursive listing, receives a `path:` heading. A blank line separates directory
sections. The initial single, non-recursive directory listing does not need a
heading.

### Hidden entries

The default excludes all names beginning with `.`. `-A` includes dot-prefixed
names other than `.` and `..`; `-a` includes both special entries as well. If
both are present, `-a` is the stronger behavior. Effective-user ID zero enables
`-A` unless `-a` is already active.

### Option precedence

The following manual-defined pairs use the rightmost occurrence:

- `-l` versus `-n`
- `-c` versus `-u`
- `-R` versus `-d`
- `-h` versus `-k`
- `-q` versus `-w`

The mutually exclusive primary sort selectors `-f`, `-S`, and `-t` also use
the rightmost occurrence. This resolves combinations that the manual does not
otherwise define. `-r` reverses the resulting primary order. Equal size or
timestamp keys are resolved lexicographically, with that complete order also
reversed by `-r`.

Unless explicitly overridden, `-q` is active when standard output is a
terminal and `-w` behavior is active otherwise.

### Output formats

Default output is one entry per line. Optional `-i`, `-s`, and long-format
fields are separated by one or more spaces and aligned to the widest value in
the current listing.

Long format contains, in order:

1. entry type and nine permission characters;
2. link count;
3. owner name or numeric ID;
4. group name or numeric ID;
5. byte size, human-readable size, or major/minor device numbers;
6. selected timestamp formatted as abbreviated month, day, and `HH:MM`;
7. pathname;
8. ` -> target` for a symbolic link.

Permission rendering supports read, write, execute/search, set-user-ID,
set-group-ID, and sticky bits, including uppercase `S` and `T` when execute is
absent. The entry-type character supports regular files, directories,
symbolic links, block and character devices, sockets, FIFOs, and FreeBSD
whiteouts when the platform exposes them. The manual's archive-state type
characters are conditionally supported only if the target headers expose
corresponding mode constants; ordinary FreeBSD files are unaffected.

For `-F`, entry type takes precedence over executable status: directory `/`,
symbolic link `@`, whiteout `%`, socket `=`, FIFO `|`, then executable regular
file `*`.

### Sizes and totals

`st_blocks` is interpreted in its native 512-byte units. For `-s`, each entry's
allocated bytes are rounded up to the selected display unit. `-k` selects 1024
bytes. Otherwise a valid positive `BLOCKSIZE` value is used, with plain byte
counts and `K`, `M`, `G`, `T`, or `P` suffixes accepted; invalid values fall
back to 512 bytes. `-h` displays allocated bytes with a compact binary-unit
suffix and overrides `-k` or `BLOCKSIZE`.

Long-format file size remains a byte count under `-k`; only `-h` changes that
field. Character and block devices show major and minor device numbers.

Every long-format directory listing prints `total` before its entries. A
listing using `-s` without long format prints `total` only when standard output
is a terminal, matching the supplied manual. Totals are calculated from raw
allocated blocks and then converted once to the selected unit.

### Sorting and names

Lexicographical sorting uses bytewise `strcmp`, giving deterministic behavior
independent of locale collation. Time sorting uses the selected modification,
change, or access timestamp including sub-second precision where FreeBSD
exposes it. Size sorting uses `st_size`.

`-q` processes pathname bytes using the active locale's printability rules and
replaces each non-printable byte with `?`. It does not alter filesystem paths
used internally. `-w` writes the original bytes.

## Architecture

### `main.c`

Owns program lifetime, invokes option parsing, selects the implicit `.`
operand, coordinates operand classification and output, and returns zero only
when no error occurred.

### `options.c` / `options.h`

Defines the `Options` structure and parses the short-option stream in order so
rightmost-wins behavior is explicit. It also resolves terminal defaults,
effective-user behavior, and `BLOCKSIZE`.

### `entry.c` / `entry.h`

Defines the owned `Entry` representation and dynamic entry lists. It collects
`lstat`/`stat` metadata, reads directories, resolves owner/group display data,
captures symlink targets, joins paths without a fixed `PATH_MAX` buffer, and
releases all allocated memory. Directory traversal consumes these entry lists
without following discovered symlinks.

### `sort.c` / `sort.h`

Implements comparators for name, size, and timestamp plus reverse ordering.
The unsorted mode preserves `readdir` order within a directory and command-line
order within an operand category.

### `format.c` / `format.h`

Formats type/permission strings, owner/group fields, sizes, block counts,
timestamps, escaped display names, symlink arrows, and `-F` suffixes. It first
computes per-listing column widths and then renders entries.

### Tests and project files

`tests/test_ls.sh` creates isolated temporary trees and checks the public CLI.
Small C unit tests may be used for pure formatters where creating the equivalent
filesystem object is privileged or unreliable. `Makefile` provides `all`,
`test`, and `clean`; `README.md` is the report; `.gitignore` excludes `my_ls`,
`*.o`, test binaries, cores, and temporary test output.

## Data Flow

1. Parse options into one immutable configuration used by later stages.
2. Classify operands using `lstat` plus limited dereferencing for
   symlink-to-directory operands.
3. Emit sorted non-directory operands.
4. For each directory operand, collect visible entries and their metadata.
5. Sort the collected entries unless unsorted mode is active.
6. Compute output widths and render the directory listing.
7. When recursion is active, recurse into eligible child directories after the
   current directory has been printed.
8. Accumulate an error flag throughout and map it to the final exit status.

## Error Handling

Every allocation and filesystem operation is checked. Diagnostics name the
program and affected path, go to standard error, and do not suppress valid
output for other operands. Unknown options and malformed invocations print a
short usage line. Failure of any requested operand or recursive directory sets
a nonzero final status.

Dynamic allocation is used for paths, names, symlink targets, and entry arrays.
All ownership is explicit, partial-construction cleanup is supported, and no
fixed-size path buffer or unchecked string operation is permitted.

## Verification Strategy

Development follows red-green-refactor cycles. `make test` will cover:

- no operands, individual file operands, directories, and mixed operands;
- default hidden filtering, `-A`, `-a`, and special dot entries;
- name, size, time, unsorted, and reverse ordering with deterministic fixtures;
- modification, change, and access timestamps;
- `-d`, `-R`, nested directories, symlink operands, and recursion boundaries;
- `-l`, `-n`, inode prefixes, block prefixes, totals, human sizes, kilobytes,
  and `BLOCKSIZE`;
- regular, directory, symlink, executable, FIFO, and socket `-F` suffixes;
- ordinary and special permission bits;
- printable and non-printable names under `-q` and `-w`;
- every rightmost-wins option pair;
- missing operands, unreadable directories where permissions permit the test,
  continued processing, diagnostics, and nonzero exit status.

Tests set a known locale and timezone where output depends on them. Whiteouts,
device files, and archive-state markers are verified at formatter level or
documented as requiring privileges/platform support when an end-to-end fixture
cannot be created safely.

Before delivery, verification consists of a clean build with all warning flags,
the complete test suite, a clean rebuild, and a check that no binary or object
artifact is tracked.

## Build Contract

The FreeBSD build uses the system `cc` and portable make syntax:

```text
cc -std=c11 -Wall -Wextra -Wpedantic -Werror
```

The normal workflow is:

```sh
make
./my_ls [options] [file ...]
make test
make clean
```

The implementation must not execute `/bin/ls`, parse its output, or copy GNU or
BSD source code. It may use documented FreeBSD/POSIX system calls and C library
interfaces.

## Acceptance Criteria

The project is accepted when it builds without warnings on FreeBSD, all listed
manual options work alone and in documented combinations, the complete test
suite passes, errors cannot crash the process, source is split across the
described modules, and the README explains features, limitations, build, run,
test, and cleanup commands. No GitHub setup is required.
